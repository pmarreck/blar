# blar Empirical Byte-Identity Audit

**Purpose**: measure blar's actual byte-identity roundtrip rate per format on real-world input. We know from inspection that some formats (PNG, ZIP-based, gzip) are *content-identical only*, and we know synthetic PDFs round-trip byte-exactly — but we don't know what happens when you feed in-the-wild files (Adobe-produced PDFs, Microsoft Word-produced .docx, GIMP-produced PNGs, camera-produced TIFFs, etc.) through `blar create -z` → `blar extract` → SHA256 compare.

The audit answers: **for each (format, generator) pair, what fraction of files round-trip byte-identically today? For the ones that don't, how big is the residual diff that difz could patch?**

This data drives Phase 3a's prioritization in `MECHA_RELEASE_PLAN.md`.

## Corpus layout

**Two corpora:**

| Subdir | Composition | Committed? | Used in CI? |
|---|---|---|---|
| `corpus_public/` | Synthetic files generated by `scripts/gen_synthetic.sh` + publicly-sourced test files (W3C, libpng test suite, PDF Association samples, etc.) | yes (small files; ≤1 MB each) | yes — reproducible |
| `corpus_local/` | Cross-section sample from `/Volumes/Fileserver` (Peter's NAS, 12 TB of in-the-wild files) | no (gitignored — may contain sensitive data) | no (Peter-only) |

The **public** corpus is the *reproducible* baseline — anyone can rebuild it with `gen_synthetic.sh` + `fetch_public.sh`, and it runs in CI. The **local** corpus is the *expressive* cross-section — covers quirks the reproducible corpus can't (old generators, vendor-specific tools, files from 2014, scanned-vs-born-digital PDFs, etc.).

Each corpus has the same subdirectory structure:

```
corpus_public/   (or corpus_local/)
  pdf/
    libreoffice/   # one subdir per known generator/source
    ghostscript/
    pandoc/
    pdflatex/
    w3c-pdf-tests/ # publicly-sourced
    wild/          # (local only) unclassified NAS samples
    ...
  png/
    imagemagick/
    libpng/
    pyPNG/
    photoshop/
    gimp/
    w3c-png-suite/ # publicly-sourced
    wild/
    ...
  docx/ xlsx/ pptx/ bmp/ tga/ tiff/ gif/ wav/ aiff/ flac/ epub/ zip/ jar/ gzip/ ...
```

In `corpus_public/`, generator subdir names indicate origin: tool names for synthetic (`imagemagick`, `ghostscript`, `pandoc`, `libflac`), descriptive names for publicly-sourced (`w3c-png-suite`, `libpng-test-suite`, `pdf-association-samples`).

In `corpus_local/`, files initially land in `<format>/wild/` (unclassified). A follow-up pass can classify by EXIF / creator metadata / file magic into per-generator subdirs once we see what's worth distinguishing.

## Running the audit

```bash
./scripts/run_audit.sh                  # both corpora (public + local)
./scripts/run_audit.sh --corpus public  # reproducible-only (what CI runs)
./scripts/run_audit.sh --corpus local   # NAS cross-section only
./scripts/run_audit.sh --format pdf     # one format only
./scripts/run_audit.sh --json results/raw.json   # JSON output for programmatic post-processing
```

## Output

`results/audit-YYYY-MM-DD.{csv,json,md}` — per-file record:

| Column | Meaning |
|---|---|
| `format` | File extension (lowercased) |
| `generator` | The subdir name under `corpus_*/<format>/` |
| `path` | Relative path within corpus_* |
| `size` | Original file size in bytes |
| `archive_size` | Size of the BLAR archive containing the file |
| `byte_identical` | `true` / `false` after round-trip |
| `residual_bytes` | If diverged: difz patch size to bring extracted bytes back to original |
| `residual_ratio` | `residual_bytes / size` — diagnostic for how close codec roundtrip came |
| `time_ms` | Wall-clock time for create+extract round trip |

A summary markdown report aggregates per (format, generator):
- Pass rate (% byte-identical)
- Median residual size for diverged cases
- Whether difz-as-backstop would close the gap (i.e. residual << file size)

## Corpus collection scripts

- `scripts/gen_synthetic.sh` — produces synthetic files in `corpus_public/<format>/<tool>/` using Nix devshell tools (ImageMagick, libreoffice, ghostscript, pdflatex, ffmpeg, libflac, etc.). All output is committed.
- `scripts/fetch_public.sh` *(TODO)* — downloads small files from known-good public sources (W3C test suites, libpng test suite, PDF Association samples, etc.) into `corpus_public/<format>/<source>/`. All output committed.
- `scripts/sample_local.sh` — random-samples N files per format from `/Volumes/Fileserver` (or `--nas-root <path>`) into `corpus_local/<format>/wild/`. Reproducible via fixed seed. Output is gitignored.

## Curating from local → public

If a `corpus_local/` file surfaces an interesting failure (rare generator, broken byte-identity) and contains no sensitive data, Peter can manually copy it into `corpus_public/<format>/<source>/` and commit. The audit will then exercise that file in CI for everyone.
